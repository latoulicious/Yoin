G′ · Manifest changeswhat "behind" counts

"Behind" = number of APK releases newer than the installed shell. CI keeps a releases[] tail of the last 5 APK builds so the sheet can count and list without a second fetch. Tail shorter than the real gap still counts as ≥ 3, which is the only threshold that matters.

{ "bundle": { "version": "2.1", "commit": "e4a7b10", "minNative": 14, … }, "apk": { "versionCode": 14, "versionName": "2.1", … }, "releases": [ { "version": "2.1", "versionCode": 14, "summary": "Insights by account" }, { "version": "2.0", "versionCode": 13, "summary": "Biometric lock" }, { "version": "1.9", "versionCode": 12, "summary": "Recurring entries" } ] } // decision, extended behind = releases.filter(r => r.versionCode > shell.build).length behind ≥ 3 → blocked one button, no dismiss, back/swipe = App.exitApp(); re-evaluated on every boot and resume 1 ≤ behind < 3 → apk needed sheet every boot, "Later" snoozes until next boot bundle.commit ≠ current → ota else → up to date offline → cannot count → not blocked (fail open, ledger must stay usable without network) // releases[] is appended by CI only on APK builds, so OTA-only pushes never inflate the count.

Failure rules: every failure is a label + a sentence under the button, never a dialog. Vermilion only when the user has something to do (retry, restart, download); offline is sumi.
