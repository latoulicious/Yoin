Category order: user-driven vs alphabetical

Storage already has categories.sort and every list reads ORDER BY system, sort. What's missing is a way to change it. Two candidates below. Each column shows Settings › Categories (where order is set) and the Record grid (where order is felt). Locked rows (Other, Fee) always sit at the bottom in both. Other stays pickable in Record; Fee stays hidden.

A · User-driven move up / down

Each row gets a ▲▼ pair. Tap swaps sort with the neighbour. Order persists in SQLite; Record grid, Insights, History filter all follow for free. No new setting.

-- repo.ts, one new fn. Swap with neighbour in same kind, same system flag.
UPDATE categories SET sort = CASE id WHEN ?1 THEN ?4 WHEN ?2 THEN ?3 END
WHERE id IN (?1, ?2);   ← ?3 = sort of ?1, ?4 = sort of ?2

A segmented switch above the list. A–Z sorts by name at read time in every screen; Manual falls back to insertion order (today's behaviour). No per-row control, so no way to say "Food first" without renaming it.

C · Drag handle ≡ · pointer events Recommended

A ≡ grip on the left. Drag starts only from the grip, so the row's tap-to-rename and the page scroll keep working. Lifted row floats, a dashed slot shows where it lands. Whole new order written once on release. Same storage as A.

Move 5 rows up 10 taps, 10 writes — 1 drag, 1 write
Touch footguns None None Grip needs touch-action:none or page scrolls instead. Long-press elsewhere unaffected. Drag past viewport edge = no autoscroll unless written
Both? Possible: A or C for storage, B as a one-shot "Sort A–Z now" button that rewrites sort. No pref, no read-time branch. Add only if asked.

A and C share storage and differ only in gesture. C costs ~45 more lines of pointer math but reads as one intent, not ten taps, and the ≡ grip is visually quieter than a ▲▼ cluster on every row. No library: HTML5 drag-and-drop does not fire on touch in a WebView, pointer events do. Fixed 46px rows make the slot index pure arithmetic. B is a display preference wearing an ordering costume — it removes control rather than adding it, and every consumer screen has to learn the pref.
