What actually differs

A · StickyB · Scroll container
Scrollbar belongs to Whole page — runs behind the pinned chrome, edge to edge Main only — starts under header, ends above nav
Rubber-band on touch Overscroll drags everything, header and nav included Chrome never moves; only content bounces
Mobile browser URL bar Page scroll collapses it — more room for content (browser only, moot in Capacitor) Inner scroll doesn't trigger collapse — bar stays
Chrome styling cost Needs bg + z-index or content bleeds through while pinned None — chrome is never overlapped
Layout constraint None — natural document flow, min-h-dvh Requires fixed height + min-h-0 on the flex chain, classic footgun
Scroll position across screens One shared scroll — switching tabs keeps page offset unless reset Scroller can live per screen — each tab remembers or resets its own
Yoin today ← this one Switch only if rubber-band moving the chrome bothers you

Both are legitimate. A is the standard mobile-web pattern: least layout code, degrades gracefully. B is the "app-like" pattern: chrome is architecture, content is a window. The visible tell on desktop is the scrollbar span; the felt tell on a phone is whether the header stretches when you over-pull.
